tmux-band: build spec

One terminal window holding every Claude Code session, with a clickable sidebar that colors each session by state and shows its pull requests. Written against tmux 3.8, iTerm2, gh 2.68 and Claude Code 2.1.x. Needs tmux 3.3+, Node 18+, a POSIX shell and (for PR status) the GitHub CLI. The focus step is macOS + iTerm2; everything else runs on any Mac or Linux box.

What
A dedicated tmux server with one session (band). Each Claude Code session is one tmux window: a sidebar pane on the left (30 columns, draggable from 20 to 60), the CLI on the right. The sidebar lists every window with a colored state (needs input, working, done), time in that state, repo · branch, and the session's pull requests with CI state. Click a row to switch, drag it to reorder, ✕ to close, ⤢ to expand to a full-width table, + new session to open a shell window in the same folder. band-attach brings the iTerm window forward and reopens the sessions a dead tmux server took with it.
How it works
State lives in tmux window user options (@band_state, @band_since, …). Claude Code hooks write them from inside the pane using $TMUX_PANE, and keep one record file per open session for restore. Each window's sidebar is a Node program that polls tmux list-windows -F once a second, draws with ANSI escapes, reads SGR mouse clicks from stdin, and polls gh for the PRs its session's transcript mentions.
Where it lives
One directory, $BAND_HOME (default ~/.local/share/band): bin/ (band-new, band-attach, band-restore, band-state.sh, band-record.sh), sidebar.mjs, sidebar-core.mjs, hooks.mjs, tmux.conf, hooks.json, and state/. An installer links bin/ into ~/.local/bin and adds the hooks to ~/.claude/settings.json.
The hard parts
Holding the sidebar at its width without breaking zoom, and telling a drag of its border from every other resize (resize-pane -x unzooms a window); hit-testing clicks against the layout that was drawn; telling "closed" from "lost with the server" at session end; tmux format expansion in window names; tmux reading -f only at server start.

Conformance: the sidebar's drawing is pinned by the test vectors in Appendix A (exact text and exact escape sequences). An implementation passes when its render and renderTable produce those strings byte for byte.

Checked 2026-11-18. The implementation that ships beside this spec was built by an agent from the spec alone. Run beside the reference sidebar on tmux 3.8 with the same windows, it drew identical screens and left identical tmux state across 14 view and click checks, and it passes all 19 vectors. Hooks, the PR badge, + new session and restore after kill-server were run with a real Claude Code 2.1.x session. Not run: the focus script against a real iTerm2, Linux.

2. Requirements

  1. All agent sessions open as windows of one tmux session in one terminal window. Closing the terminal window detaches; sessions keep running.
  2. band-attach brings the existing iTerm window forward when a client is attached in iTerm2, and opens one attached window when no client is attached in iTerm2 (none at all, or only in another terminal or over ssh).
  3. When the tmux server dies (crash, kill-server, reboot), band-attach offers to reopen the sessions it took with it, each resumed with claude --resume in its folder, under its title and tag. A session closed on purpose is not reopened.
  4. Mouse everywhere: click a sidebar row to switch to that session; click inside the CLI pane to type there; scroll works in panes.
  5. State colors per session: needs input (orange ●, 256-color 214), working (blue ◌, 75), done (green ✓, 71), seen (grey ✓, 244). A done session turns seen once you focus it, so green means "finished and you haven't looked".
  6. Each row shows title, state + time in state, an optional tag (e.g. work for a second account), repo · branch of the pane's current directory, and a badge for the PRs the session mentioned (number, CI mark or merged/closed).
  7. ✕ on a row closes that window. If the state is not done or seen, the row's state line becomes Close? yes no first.
  8. + new session, under the last row, opens a new window with a sidebar and a plain login shell, in the folder of the window it was clicked in, and switches to it. No CLI starts: the user picks the account and provider by what they type.
  9. ⤢ expands to the table view; ⤡, any key, or clicking a row (which also switches to it) collapses.
  10. Both views list the sessions in one order, the tmux window order. Dragging a row in either view moves it; the list previews the new order while the row is held, and every window's sidebar shows the result.
  11. The sidebar is 30 columns wide until its border is dragged; any width from 20 to 60 sticks, in every window, across terminal resizes, window switches and a restart of the tmux server.
  12. A session's title keeps up to 120 characters. Each view shows as much as it has room for, so the table shows what the sidebar cuts.
  13. Does not touch the user's own ~/.tmux.conf or any other tmux server.

3. Layout on disk and data model

Files

B = $BAND_HOME at install time (default ~/.local/share/band). Every script finds B from its own location, so the hook commands written into settings need no environment: resolve $0 through symlinks first (the installer links the commands into ~/.local/bin; loop on readlink, resolving a relative target against the link's directory), then B=$(CDPATH= cd "$(dirname "$resolved")/.." && pwd) (with CDPATH set, cd prints the directory and the value doubles). Directory mode 0700.

Shared resolution, used by every script:

  • TMUX_BIN = the first of /opt/homebrew/bin/tmux, /usr/local/bin/tmux, /usr/bin/tmux that exists, else command -v tmux. GH_BIN and GIT_BIN the same with gh and git. NODE_BIN = the first of the same three folders, then command -v node, whose major version is 18 or more (a distribution's old /usr/bin/node must not win over a newer one on PATH); BAND_GH and BAND_OSASCRIPT override gh and osascript for tests. The server's clean environment (section 10) drops BAND_GH, so a test sets it on the server with set-environment -g before opening the window whose sidebar should see it. Always call them by absolute path: a hotkey app or launchd has no Homebrew PATH.
  • SOCK=B/state/tmux.sock. Every tmux call is "$TMUX_BIN" -S "$SOCK" … (quoted, so a B with spaces works). Only band-new adds -f B/tmux.conf, because only it can start the server.
  • File age in seconds: $(date +%s) minus the mtime from stat -f %m (macOS), falling back to stat -c %Y (Linux).
  • tmux -F formats in this spec separate fields with a real tab character (written \t here).
  • Escape sequences are written with spaces between them for reading (ESC[?1002h ESC[?1006h); the bytes have no spaces.

Every value the launcher and the sidebar write to an option goes through optionValue(s, max = 40) (the hooks write @band_wait, @band_session and @band_transcript as their scripts show, unshortened): replace each control character (U+0000–001F, U+007F–009F) with a space, collapse runs of whitespace to one space, trim, keep the first max code points, then strip trailing ; and whitespace. @band_repo uses max 60; @band_pr uses max 60 and then removes every #.

The sidebar reads everything with one call (tab-separated, window name last because it may contain tabs; join the remaining fields with a space):

tmux -S $SOCK list-windows -t =band -F \
  '#{window_id}\t#{window_active}\t#{@band_state}\t#{@band_tag}\t#{@band_since}\t#{@band_wait}\t#{@band_model}\t#{@band_repo}\t#{@band_pr}\t#{window_name}'

Parse each line into { id, active, state, tag, since, wait, model, repo, pr, name }: skip a line whose id does not match ^@\d+$; active is field === '1'; since is the number when the field is all digits, else 0; every text field has control characters removed.

  • exit-empty is a server option (-s): closing the last window leaves the server running, so the record hook reads that as "closed", not "lost". Probed on tmux 3.8: list-sessions exits 0 on a server with no session and 1 when no server answers.

  • extended-keys lets Shift+Enter and similar reach Claude Code.

5. Component: launcher band-new

Usage: band-new [-n title] [-t tag] [-m model] [-C dir] [--no-attach] [-- command words…], e.g. band-new -n "fix login" -C ~/code/web-app -- claude. The words after -- are joined with single spaces into the command line, which is typed into a shell, so a caller quotes for that shell. With no --, the command line is claude. -C defaults to the current directory; a folder that does not exist is passed through, so a restore of a deleted folder still opens a window (tmux 3.8 opens the pane in $HOME without an error).

  1. Resolve TMUX_BIN, NODE_BIN and B (section 3).
  2. Title: first non-empty line of -n (else the folder's basename, else session), then optionValue(title, 120) (section 3), then # → ##. Tag and model go through optionValue(…, 40) too. optionValue counts code points; implement it with "$NODE_BIN" -e or by importing it from sidebar-core.mjs, not with cut, which counts bytes or characters depending on locale. For a directory containing # or ending in ;, skip -c and instead run the tmux command from inside that directory (cd "$dir" && …), so the window inherits it.
  3. If has-session -t =band succeeds: when B/state/conf-sourced is missing or older than B/tmux.conf, run source-file B/tmux.conf and touch conf-sourced (tmux reads -f only at server start, so a config edit otherwise never reaches a running server). Then new-window -d -t band: -n "$title" -c "$dir" -P -F '#{window_id} #{pane_id}'.
    Otherwise: start the server from a clean environment (section 10, "Server environment") with new-session -d -s band -n "$title" -c "$dir" -x 200 -y 50 -P -F '#{window_id} #{pane_id}', then touch B/state/server-started and B/state/conf-sourced. (A server that answers list-sessions but has no band session, after its last window closed, takes this branch too; new-session works on it.)
  4. Parse @N %M from the output (fail if it doesn't match ^@\d+ %\d+$). Then, killing the window if any of these fail: 
    set-option -w -t @N @band_since "$(date +%s)"
set-option -w -t @N @band_tag   "$tag"      # if given
set-option -w -t @N @band_model "$model"    # if given
split-window -d -hb -l 30 -t %M  "$NODE_BIN" B/sidebar.mjs "$TMUX_BIN" "$SOCK"
send-keys -t %M -l -- "$command_line"
    Then send-keys -t %M Enter; a failure here is logged, not fatal (the line is typed; retrying would launch twice). The CLI runs in the pane's login shell, so when it exits you get a shell back in that window.
  5. Unless --no-attach: if list-clients -t =band -F '#{client_tty}' prints nothing, select-window -t @N and run B/bin/band-attach --no-restore >&2 (section 8: it opens one terminal window, with its 10 s guard; its output goes to stderr so stdout carries only @N). If a client is attached, do nothing: the new window appears in the sidebar without taking focus.
  6. Print @N on stdout.

A second account: band-new -t work -- CLAUDE_CONFIG_DIR=~/.claude-work claude. The record hook stores the config dir so a restore resumes under the same account.

6. Component: hooks

Claude Code runs hooks as children of the CLI, which runs in the pane, so $TMUX and $TMUX_PANE are in the hook's environment. Both scripts exit at once outside the band server: the socket path is the part of $TMUX before the first comma, and the check is [ "${TMUX%%,*}" -ef "$SOCK" ] (same file, so /tmp vs /private/tmp spellings match). A hook that prints anything or exits non-zero can change the CLI's behaviour (a PermissionRequest hook's output is read as a decision), so every path exits 0 with no output.

Window lookup must be checked. When the pane is gone (its window was just closed with ✕), tmux 3.8 answers display-message -p -t %<gone> '#{window_id}' with an empty line and exit status 0, and set-option -w -t "" then writes to the current window. Both hooks exit unless the window id matches ^@[0-9]+$. Probed 2026-11-17.

Fields are read from the hook's JSON input with sed. Each key appears once in the input, which is one line; the patterns do not unescape JSON, so a path containing " or \ is read wrong (acceptable here).

6.1 bin/band-state.sh: live state

#!/bin/sh
# band-state.sh <working|input|done|clear>
# (resolve B and TMUX_BIN as in section 3; on any failure: exit 0)
SOCK="$B/state/tmux.sock"
[ -n "$TMUX_PANE" ] && [ -n "$TMUX" ] || exit 0
[ "${TMUX%%,*}" -ef "$SOCK" ] || exit 0
t() { "$TMUX_BIN" -S "$SOCK" "$@" 2>/dev/null; }
case "$1" in working|input|done|clear) state=$1 ;; *) exit 0 ;; esac
wait=""
input=$(cat)
if [ "$state" = input ]; then
  tool=$(printf '%s' "$input" | sed -n 's/.*"tool_name" *: *"\([^"]*\)".*/\1/p' | head -n 1)
  case "$tool" in
    AskUserQuestion) wait="question" ;;
    ExitPlanMode)    wait="plan approval" ;;
    "")              wait="input needed" ;;
    *)               wait="permission: $tool" ;;
  esac
fi
[ "$state" = clear ] && state=""
win=$(t display-message -p -t "$TMUX_PANE" '#{window_id}')
printf %s "$win" | grep -Eq "^@[0-9]+\$" || exit 0
# A claude started inside this session (claude -p from a tool call) is not the window's.
id=$(printf '%s' "$input" | sed -nE 's/.*"session_id" *: *"([0-9a-f-]{36})".*/\1/p' | head -n 1)
owner=$(t show-options -wqv -t "$win" @band_session)
[ -n "$owner" ] && [ -n "$id" ] && [ "$owner" != "$id" ] && exit 0
cur=$(t show-options -wqv -t "$win" @band_state)
[ "$cur" = seen ] && [ "$state" = done ] && state=seen
if [ "$cur" != "$state" ]; then
  t set-option -w -t "$win" @band_state "$state" \; set-option -w -t "$win" @band_since "$(date +%s)" >/dev/null
fi
t set-option -w -t "$win" @band_wait "$wait" >/dev/null
exit 0

The wait values are all under 40 characters except a long tool name; truncate it with optionValue semantics if you like, the sidebar fits it anyway.

6.2 bin/band-record.sh: the restore record

#!/bin/sh
# band-record.sh <start|end>  (any other argument: exit 0)
# (resolve B and TMUX_BIN as in section 3; on any failure: exit 0)
SOCK="$B/state/tmux.sock"; REC="$B/state/sessions"
[ -n "$TMUX_PANE" ] && [ -n "$TMUX" ] || exit 0
[ "${TMUX%%,*}" -ef "$SOCK" ] || exit 0
case "$1" in start|end) ;; *) exit 0 ;; esac
t() { "$TMUX_BIN" -S "$SOCK" "$@" 2>/dev/null; }
input=$(cat)
UUID="^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\$"
# The JSON string value of a key, with \" \\ and \/ unescaped.
field() {
  printf '%s' "$input" | sed -nE 's/.*"'"$1"'" *: *"((\\.|[^"\\])*)".*/\1/p' | head -n 1 | sed -E 's/\\(["\\/])/\1/g'
}
id=$(field session_id)
printf %s "$id" | grep -Eq "$UUID" || exit 0
win=$(t display-message -p -t "$TMUX_PANE" '#{window_id}')
owner=
printf %s "$win" | grep -Eq "^@[0-9]+\$" && owner=$(t show-options -wqv -t "$win" @band_session)
if [ "$1" = end ]; then
  # The pane outlives an exit typed in it. A pane that is gone means a closed
  # window (the sidebar removed the record) or a dead server (the record stays).
  [ -n "$owner" ] && [ "$owner" = "$id" ] && rm -f "$REC/$id" 2>/dev/null
  exit 0
fi
printf %s "$win" | grep -Eq "^@[0-9]+\$" || exit 0
# The CLI's pid: the first ancestor that is not a shell.
pid=$PPID; n=0
while [ "$n" -lt 4 ]; do
  comm=$(ps -o comm= -p "$pid" 2>/dev/null) || break
  case "${comm##*/}" in
    sh|bash|zsh|dash|-sh|-bash|-zsh) pid=$(ps -o ppid= -p "$pid" 2>/dev/null | tr -d ' ') ;;
    *) break ;;
  esac
  n=$((n + 1))
done
printf %s "$pid" | grep -Eq "^[0-9]+\$" || pid=
# Another CLI still owns the window: this one was started inside its session.
if [ -n "$owner" ] && [ "$owner" != "$id" ]; then
  held=$(t show-options -wqv -t "$win" @band_pid)
  if printf %s "$held" | grep -Eq "^[0-9]+\$" && [ "$held" != "$pid" ] && kill -0 "$held" 2>/dev/null; then
    exit 0
  fi
  rm -f "$REC/$owner" 2>/dev/null
fi
t set-option -w -t "$win" @band_session "$id" \; set-option -w -t "$win" @band_transcript "$(field transcript_path)" \; set-option -w -t "$win" @band_pid "$pid" >/dev/null
cwd=$(field cwd)
title=$(t display-message -p -t "$win" '#{window_name}')
tag=$(t show-options -wqv -t "$win" @band_tag)
mkdir -p "$REC" 2>/dev/null && chmod 700 "$REC" 2>/dev/null
{ printf '%s\n%s\n%s\n%s\n' "$cwd" "$title" "$tag" "${CLAUDE_CONFIG_DIR:-}" > "$REC/$id.tmp"; } 2>/dev/null \
  && mv "$REC/$id.tmp" "$REC/$id" 2>/dev/null
exit 0

Who owns the window. Hooks run in every process that inherits the pane's environment, so a claude -p started from a tool call fires them too. SessionStart stores the CLI's pid (@band_pid, the first ancestor of the hook that is not a shell) beside its session id; a start from another session is ignored while that pid is alive and is not the caller's own, and the state hook ignores any event whose session_id is not the window's. /clear and compaction keep the pid, so they take the window over; a new CLI started after the first one exited or died does too.

End without a sleep. SessionEnd hooks get about 1.5 s. The pane outlives an exit typed in it, so end removes the record only when the pane still exists and the window is this session's. A pane that is gone means the window was closed (the sidebar removed the record first) or the server died (no answer, the record stays and is offered for restore). --resume fires SessionStart with the same id and rewrites the record. Verified with Claude Code 2.1.x on 2026-11-18: SessionStart wrote the id, pid and record; UserPromptSubmit, Stop, PermissionRequest (permission: Bash) and PostToolUse set the states; a nested claude -p left the window with its parent; /exit and ✕ removed the record; kill-server kept it.

6.3 B/hooks.json (and the block the installer merges into settings)

{
  "hooks": {
    "SessionStart":      [{ "hooks": [{ "type": "command", "command": "[ ! -x B/bin/band-record.sh ] || B/bin/band-record.sh start", "timeout": 5 }] }],
    "UserPromptSubmit":  [{ "hooks": [{ "type": "command", "command": "[ ! -x B/bin/band-state.sh ] || B/bin/band-state.sh working", "timeout": 5 }] }],
    "PermissionRequest": [{ "matcher": "*", "hooks": [{ "type": "command", "command": "[ ! -x B/bin/band-state.sh ] || B/bin/band-state.sh input", "timeout": 5 }] }],
    "PostToolUse":       [{ "matcher": "*", "hooks": [{ "type": "command", "command": "[ ! -x B/bin/band-state.sh ] || B/bin/band-state.sh working", "timeout": 5 }] }],
    "Stop":              [{ "hooks": [{ "type": "command", "command": "[ ! -x B/bin/band-state.sh ] || B/bin/band-state.sh done", "timeout": 5 }] }],
    "SessionEnd":        [{ "hooks": [{ "type": "command", "command": "[ ! -x B/bin/band-state.sh ] || B/bin/band-state.sh clear", "timeout": 5 },
                                      { "type": "command", "command": "[ ! -x B/bin/band-record.sh ] || B/bin/band-record.sh end", "timeout": 5 }] }]
  }
}

B is replaced by the absolute install path. The [ ! -x … ] || guard makes every hook a silent no-op once the install folder is deleted; without it each event in every Claude Code session on the machine would fail with "not found". The 5 s timeout bounds a tmux server that stopped answering. PermissionRequest fires for permission dialogs, the plan-approval dialog and AskUserQuestion; PostToolUse clears input once a dialog is answered and the tool runs. Do not hook Notification idle_prompt to input: it fires about a minute after every finished turn and would turn every done session orange.

7.2 Helpers (exact)

  • Escapes. fg(n, s) = ESC[38;5;{n}m + s + ESC[39m. bold(s) = ESC[1m + s + ESC[22m. Active row background = ESC[48;5;237m at the start of each of the row's three content lines; every content line (active or not) ends with ESC[0m.
  • charWidth(cp): 0 for U+0300–036F, U+200B–200F, U+FE00–FE0F. 2 for U+1100–115F, U+2E80–A4CF, U+AC00–D7A3, U+F900–FAFF, U+FE30–FE4F, U+FF00–FF60, U+FFE0–FFE6, U+1F300–1FAFF, U+20000–3FFFD. Else 1. textWidth sums over code points.
  • fit(s, w): w ≤ 0 → empty. If textWidth(s) ≤ w: s padded with spaces to w. Else take code points while the running width plus the next one's width ≤ w − 1, append …, pad with spaces to w.
  • age(now, since): empty if either is 0 or now < since; under 60 s now; under 3600 ⌊s/60⌋m; under 86400 ⌊s/3600⌋h; else ⌊s/86400⌋d.
  • stateText(row) = [label, age] without empties, joined by one space.
  • repoLabel(rev, cwd): rev is the output of git -C cwd rev-parse --path-format=absolute --git-common-dir --abbrev-ref HEAD (null on failure). Split it on newline into common dir and branch. If the common dir is missing or not absolute: basename(cwd). Repo = basename of its parent when the common dir's basename is .git (worktrees show the main repo), else its basename minus a trailing .git. Result repo · branch, with branch detached when empty or HEAD.
  • needsConfirm(state) = state is neither done nor seen.

7.3 Normal view: layout, render, hit

  • layout({rows, height}): capacity = max(0, ⌊(height − 2 − 2)/4⌋) (the last 2 are kept for the new-session line); activeAt = index of the active row, or 0; start = 0 if all fit, else max(0, min(activeAt − capacity + 1, n − capacity)). Returns { row, top } for rows start…start+capacity−1, where top = 3 + 4i is the 1-based line of the row's blank spacer.
  • Line 1: if width > 7, bold(fit(' band', width − 2)) + fg(244, '⤢ '); else bold(fit(' band', width)).
  • Line 2: fg(244, fit(text, width)), text 1 needs input, N need input, or nothing waiting.
  • A held row (dragging is its id) uses background 239 in place of the active background, and fg(75, '↕') in place of its state mark on the title line. Nothing else about it changes.
  • Per row, four lines:
    1. fit('', width) (no escapes).
    2. Title. If width > 6: ' ' + fg(color, mark) + ' ' + (active ? bold(name) : name) + fg(244, ' ✕ ') with name = fit(row.name, width − 6); else fit('', width). Prefixed with the active background, suffixed ESC[0m.
    3. State. When confirming this row: fit(' Close? yes no', width). Else: label = ' ' + stateText; tag = row.tag ? ' ' + row.tag : ''; badge = prBadge(parsePrs(row.pr)); badgeText = badge && width − textWidth(badge.text) − 2 ≥ 12 ? ' ' + badge.text + ' ' : ''; text = fit(label + tag, width − textWidth(badgeText)); output fg(color, text.slice(0, label.length)) + fg(244, text.slice(label.length)) + (badgeText ? fg(badge.color, badgeText) : '') (slice by UTF-16 units). Same prefix/suffix.
    4. fg(244, fit(' ' + row.repo, width)), same prefix/suffix.
  • After the rows: fit('', width), then fg(244, fit(' + new session', width)), neither with a background or ESC[0m. newLine = 2 + 4 × (rows laid out) + 2, the line this text lands on.
  • Return the first height lines.
  • hit({x, y, …}) (1-based): y = 1 and x > width − 3 → expand. y = newLine and x ≤ 14 → new. Else find the laid-out row with top ≤ y < top + 4; line = y − top. If confirming that row and line is 2: yes (x 10–12), no (16–17), else none. Line 1 and x > width − 3 → close. Any other line of the row, the spacer included → select. No row → none.

7.4 Table view: renderTable, hitTable

  • Columns in order: STATE 19, SESSION 16 (flex), REPO · BRANCH 30, PR · CI 28, WAITING ON 20, MODEL · MODE 20. Drop columns from the right while more than two remain and 1 + Σwidths + 3 > width. Then SESSION's width becomes max(16, 16 + width − total), where total = 1 + Σwidths + 3 over the columns kept. A table narrower than the two kept columns (39) is drawn wider than the pane, not clipped. renderTable also returns only the first height lines. id is null for none, expand and collapse, and the confirming row for yes and no.
  • Order: the rows as given, which is the tmux window order. No sorting by state. A held row draws its state cell as fg(75, '↕') + fg(color, fit(' ' + stateText, 18)) and uses background 239.
  • tableLayout: capacity = max(0, height − 3); same start rule as layout; row i is on line 4 + i.
  • Line 1: summary band N session(s), M need(s) input (1 session, 1 needs). If width > 17: bold(fit(summary, width − 11)) + fg(244, '⤡ collapse '); else bold(fit(summary, width)). Line 2: fit('', width). Line 3: fg(244, fit(' ' + titles each fit to its width, joined, width)).
  • Rows: confirming → background + fit(' Close? yes no', width) + ESC[0m. Else background + ' ' + cells + spaces to fill max(0, width − (1 + Σwidths) − 3) + fg(244, ' ✕ ') + ESC[0m. Cells at column width w:
    • state: fg(color, fit(mark + ' ' + stateText, w))
    • session: (active ? bold(fit(name, w − 1)) : fit(name, w − 1)) + ' '
    • repo: fit(repo, w − 1) + ' '
    • PR: fg(cell.color, fit(cell.text, w − 1) + ' ') with cell = prCell(parsePrs(row.pr))
    • waiting: fg(state color, fit(wait, w − 1) + ' ')
    • model: fg(244, fit(model, w))
  • hitTable: line 1 → collapse when x > width − 11, else none. A row's line: confirming → yes/no/none as above; x > width − 3 → close; else select.

7.5 PR helpers

  • parsePrs(value): split on ,, keep items matching ^([1-9]\d{0,8}):([omc]):([pfr]?)$, first 3, as { number, state, ci }. prValue(prs) is the inverse (same filter and cap).
  • lead PR: among open PRs, the first with CI f, else the first with r, else with p, else with no CI; so any open PR leads over merged or closed ones. With no open PR, the last PR in the list.
  • prColor(pr): merged 141, closed 244, else the CI color, else 244.
  • prBadge(prs): null when empty. Text = #<lead number> + (+<n−1> when n > 1) + (' ' + mark for an open lead with CI, ' merged'/' closed' for a closed lead, nothing for an open lead without CI). Color = prColor(lead).
  • prCell(prs): text = each PR as #<n> <word> joined by , ; color = prColor(lead); empty text and 244 when none.

7.6 The program loop (sidebar.mjs)

Start: write ESC[?1002h ESC[?1006h ESC[?25l (1002 reports presses, releases and motion while a button is down); stdin raw mode (when a TTY), UTF-8. Exit (SIGHUP, SIGTERM, SIGINT, stdin end, or the quit conditions below): write ESC[?1006l ESC[?1002l ESC[?25h ESC[0m, leave raw mode, exit 0. Size = stdout.columns || 30 by stdout.rows || 24. Run source-file B/tmux.conf without waiting for it (a server reads -f once, and hooks from an older config would resize the pane behind this script's back). Start a 1 s interval running tick, and run one tick at once.

tick (skip if a tick is in progress):

  1. Remember epoch = zoomEpoch. display-message -p -t $TMUX_PANE '#{window_id}\t#{pane_width}\t#{window_panes}\t#{session_attached}\t#{window_active}\t#{window_zoomed_flag}\t#{window_width}\t#{@band_sidebar_width}'. On failure count it; at 3 consecutive failures quit; return. A window id that does not match ^@\d+$ is a failure too: for a pane that is gone, tmux 3.8 prints an empty line and exits 0. Else reset the count.
  2. ownWindow = window id. If epoch === zoomEpoch, zoomed = flag === '1'.
  3. If window_panes is 1: quit (the CLI pane is gone; exiting closes the window).
  4. If zoomed and the window is not active: setZoom(false).
  5. If not zoomed: holdWidth (7.8) with this tick's pane width, option value, window width and active flag.
  6. Repo counter: on its values 0, 5, 10, … (it counts ticks that reach this step, starting at 0) run noteRepo: read #{pane_current_path} of <ownWindow>.1; if non-empty run the git command from repoLabel (2 s timeout); label = optionValue(repoLabel(rev, cwd), 60); write @band_repo only when it differs from the last value written successfully.
  7. Kick the PR poller (7.7) without awaiting it.
  8. If the window is not active: return unless the inactive counter is at 0, 5, 10, … (a separate counter, incremented on each inactive tick, reset to 0 whenever the window is active).
  9. list-windows (section 3) and parseWindows; keep the old rows if the call fails. Note the own row's state for the PR poller's "became done" trigger.
  10. If this window's row has state done, the window is active, session_attached > 0, and not zoomed: write @band_state seen and set the row's state locally. @band_since is not stamped on this change, so a seen row keeps the time it finished.
  11. If the confirming row no longer exists, clear the confirmation. draw().

Kept from the reference build, and pinned by the vectors: the table title says 0 need input while the normal view says nothing waiting; the expand hit zone is the last 3 columns although ⤢ draws in 2; the expand and collapse hit zones exist even at widths where their glyphs are not drawn.

draw: render with now = ⌊Date.now()/1000⌋ (table when zoomed). If zoomed:width:height changed since the last draw, prefix ESC[2J. Write each line i at ESC[{i+1};1H; if fewer lines than height, follow with ESC[{n+1};1H ESC[J. Also redraw on stdout resize.

setZoom(on): zoomEpoch++; zoomed = on; if-shell -F -t $TMUX_PANE '#{==:#{window_zoomed_flag},<on ? 0 : 1>}' 'resize-pane -Z -t $TMUX_PANE'. (resize-pane -Z toggles; the epoch stops a tick that read the flag before the click from writing it back.) focusSession(w) = select-pane -t <w>.1.

Click timing. Hit-testing uses stdout's size, which can lag tmux's pane size for a moment after a zoom change, and a tick that started after a click can read the zoom flag before the zoom command lands. The reference build accepts both; a build may also ignore the zoom flag from any tick that overlaps a zoom command (count zoom commands in flight and bump the epoch again when one returns).

stdin: find every ESC [ < b ; x ; y (M|m) in the chunk. For each: M with b = 0 is a press, press(x, y); M with b = 32 is motion with the button down, dragTo(y); m with b = 0 is the release, release(). A chunk with no mouse sequence at all is a keypress: drop any held row, zoomEpoch++, zoomed = false, focusSession(ownWindow) (selecting the CLI pane unzooms the window).

Dragging. The logic is four pure functions in sidebar-core.mjs; sidebar.mjs holds one variable, drag (null when no row is held). Times are milliseconds.

  • press(x, y): if a row is still held (its release never came), clear drag, draw and stop: the press landed on a preview that is not the real order. Otherwise hit-test as click does. Any result but select: run click(x, y). select: drag = dragBegin(…) and nothing else yet, so a row is selected on the release, not the press.
  • dragBegin({ id, y, rows, height, zoomed, now }) → { id, y, at: now, last: now, engaged: false, moved: false, order: ids of rows, start }, where start is the index of the first row the view shows now.
  • layout, tableLayout, render and renderTable take an optional start: when given, the first row shown is min(max(start, 0), max(0, n − capacity)) in place of the active-row rule, so the view holds still while a row is held.
  • dragMove(drag, { y, rows, height, zoomed, now }) → the next drag, with last = now:
    1. Not engaged yet: with dy = |y − drag.y|, stay unengaged and return when dy < 1, or dy < 2 and now − drag.at < 250 (a click that slips one line is still a click). Else engaged = true.
    2. list = dragRows(rows, drag): the rows in drag.order (ids no longer present dropped), then any row not in it.
    3. Lay list out with start. Each shown row spans lines top … top + 3 (normal) or its one line (table). The first and last rows shown are the scroll zones: if y is on or above the first shown row's last line and start > 0, start −= 1; else if y is on or below the last shown row's first line and more rows follow, start += 1. Lay out again. (The table's last row sits on the pane's last line, so there is no line below it to scroll from.)
    4. over = the last shown row whose first line is at or above y, or the first shown row. If it is not the held row: order = moveId(ids of list, id, over) (remove the id, insert it at the index over had) and moved = true.
  • dragEnd(drag, rows) → what the release does: { kind: 'none' } when there is no drag or its row is gone; { kind: 'select', id } when it never moved; else with order = ids of dragRows(rows, drag), { kind: 'none' } when that equals the current order (dragged away and back) and otherwise { kind: 'move', args: moveArgs(order, id) }. moveArgs is move-window -d -b -s id -t <the id after it in order>, or move-window -d -a -s id -t <the id before it> when it is last; null for a lone window.
  • dragView(rows, drag, now) → what draw renders: { rows: dragRows(rows, drag), dragging: drag.id, start: drag.start } while the drag is engaged and not expired, else { rows, dragging: null, start: null }. dragExpired(drag, now) = now − drag.last > 10000: tmux sends a release to the pane under the pointer, so a drag that ends outside the sidebar gets no release, and one with no mouse event for 10 s is over.
  • dragTo(y) (motion): when a row is held, drag = dragMove(…) and draw.
  • release(): take drag and clear it. select: select(id) = clear confirm; setZoom(false); select-window -t id; focusSession(id); tick; draw. move: clear confirm and run one tmux command: the args, then ; move-window -r -t =band:, then ; select-window -t <the window that was active>; then, when not zoomed, focusSession(ownWindow); tick. Draw in every case.
  • In tick, before the draw: clear drag when it has expired or its row is gone.

Probed on tmux 3.8: a pane that asked for mouse events gets the drag (MouseDrag1Pane runs send -M); move-window -a/-b leaves a gap in the indexes, and new-window fills the lowest gap, so without move-window -r the next session would appear mid-list; the current window is an index, so after a move it can name another window, hence the select-window.

click(x, y): hit-test with hitTable when zoomed, else hit. Then:

ResultAction

newWindow(): read #{pane_current_path} of <ownWindow>.1. new-window -t =band: -n terminal [-c <dir>] -P -F '#{window_id} #{pane_id}', without -d so it becomes the current window; skip -c when the folder is empty, contains # or ends in ;, as band-new does (section 5). 7.7 PR poller (inside each sidebar, for its own window)

  • When: at most one poll runs at a time. Nothing happens while the own window has no @band_transcript (read it each kick). A poll starts when none has run yet for the current transcript path, when 180 s have passed since the last poll, or when a "became done" trigger is pending and 30 s have passed since the last poll. A trigger becomes pending when the own row's state read in step 9 is done and the previous read was something else (the first read never triggers); it clears when a poll starts.
  • URLs: read the transcript JSONL from the last byte offset consumed (start at 0; restart at 0, with an empty URL list, when the path changes or the file is now shorter than the offset). Consume complete lines only; a trailing partial line waits for the next poll. For each line that parses as JSON: from type: "assistant" entries, every message.content[] item with type: "text"; from type: "user" entries, every message.content[] item with type: "tool_result" (its content is a string or an array of {type: "text", text}). Match /(?<=^|[\s([])https:\/\/github\.com\/[\w.-]+\/[\w.-]+\/pull\/\d+/g. Keep unique URLs in first-seen order, at most 10: when an eleventh arrives, drop the oldest. The window's PRs are the last 3 of the list. One poll reads at most 8 MB of the transcript and the next continues from the offset; a single line longer than that is skipped.
  • Fetch: for each of the window's 3 URLs whose cached entry is missing, or not merged and at least 180 s old: gh pr view <url> --json state,statusCheckRollup (10 s timeout). state OPEN/MERGED/CLOSED → o/m/c. CI from statusCheckRollup (each item has conclusion, empty while running, or state): any of FAILURE, ERROR, TIMED_OUT, CANCELLED, ACTION_REQUIRED, STARTUP_FAILURE → f; else any item that is not SUCCESS, NEUTRAL or SKIPPED → r; else p if there are items, else empty. On a gh failure stop fetching for this poll (append one line to B/state/sidebar.log the first time per process) and go on to the write.
  • Write: the window's PRs with a cache entry that is merged or under 15 min old, in list order, as prValue, through optionValue(v, 60) with # removed, into @band_pr, only when it differs from the last value this process wrote (initially none, so the first poll writes even an empty value).

7.8 The sidebar's width

One width for every window, held in the global tmux option @band_sidebar_width and in the file B/state/sidebar-width. The user changes it by dragging the border between the two panes, which tmux does itself with mouse mode on. Probed on tmux 3.8: a border drag changes the pane's width live, fires neither window-resized nor after-select-window, and leaves the window's width alone.

  • parseWidth(value): the number when the trimmed value is 1 to 3 digits and from 20 to 60, else null.
  • widthStep(now, prev, saved) → { set, resize }, each a width or null. now is this tick's reading { own, option, windowWidth, active, panes }, prev the last one that can be trusted (null when there is none), saved the file's content.
    1. Option not a valid width (unset on a new server): option = parseWidth(saved) ?? 30, and set it.
    2. Else dragged, when all hold: the window is active and has 2 panes now, there is a prev and it was active with 2 panes, prev.own ≠ own, prev.windowWidth = windowWidth, and prev.option parses to the same width. Then option = clamp(own, 20, 60), and set it when it changed.
    3. target = max(1, min(option, windowWidth − 21)): when the terminal is narrower than the width asks for, the session pane keeps 20 columns and the option is left alone. resize = target unless own already equals it.
    A drag is the only thing that changes a pane's width and nothing else in a reading. The conditions rule out, in order: a window switch (hooks from another config may have resized it), a third pane opening or closing, a reading that did not change, a terminal resize, and another window's sidebar changing the option.
  • holdWidth(reading) in sidebar.mjs, run by tick only when both the local zoomed and the reply's zoom flag are off; otherwise forget prev (a reply read before a zoom or unzoom carries the other state's width). Call widthStep, reading the file only when the option is not a valid width. Remember the reading as prev. On set: set-option -g @band_sidebar_width <n>, remember the option as that value, and save the file. On resize, when this process's last resize was ≥ 500 ms ago: resize-pane -t $TMUX_PANE -x <n>, then forget prev: tmux gives the pane what fits with no error, so the next reading must not be compared with what was asked for. The size fallback and newWindow's split use the current width.
  • Saving the file: skip when the file already holds that width; else write sidebar-width.<pid> and rename it over. On a new server every window's sidebar starts at once and reads this file; a plain rewrite lets one read it empty and fall back to 30.
  • The launcher still splits at 30 (section 5); the new sidebar's first tick resizes it.

8. Component: band-attach (focus the iTerm window)

Closing the terminal window only detaches, so the usual way back is band-attach (bind it to a global hotkey with Raycast, Hammerspoon or skhd). It finds the iTerm tab that already shows the session by tty and raises it, so you never get a second client.

  1. Unless --no-restore: N = number of lines from band-restore --list. If N > 0: with --restore, or when stdin is a TTY and the answer to Reopen 1 session? [Y/n] / Reopen N sessions? [Y/n] is empty or starts with y/Y (EOF counts as no), run band-restore --no-attach. No TTY and no flag means skip.
  2. If has-session -t =band fails, print no band session and exit 0.
  3. 9. Component: band-restore (after the tmux server dies)

A dead tmux server takes every pane's process with it, so each session ends together. The record hook keeps a session's record when no server answers at its end; a close (✕, /exit, closing the last window) happens on a live server and removes it. A reboot leaves every record with no server running.

#!/bin/sh
# band-restore [--no-attach | --list]: reopen up to 12 sessions a previous tmux server took with it.
# (resolve B and TMUX_BIN as in section 3)
D="$B/state"; SOCK="$D/tmux.sock"; REC="$D/sessions"; MARK="$D/server-started"
UUID="^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\$"
[ -d "$REC" ] || exit 0
find "$REC" -type f -mmin +1440 -delete
if "$TMUX_BIN" -S "$SOCK" list-sessions >/dev/null 2>&1; then
  live=$("$TMUX_BIN" -S "$SOCK" list-windows -a -F '#{@band_session}')
  for f in $(find "$REC" -type f -newer "$MARK" -exec basename {} \;); do
    printf '%s\n' "$live" | grep -qx "$f" || rm -f "$REC/$f"
  done
  lost=$(find "$REC" -type f ! -newer "$MARK" -exec ls -tr {} + 2>/dev/null | xargs -n1 basename 2>/dev/null)
else
  lost=$(ls -tr "$REC")
fi
if [ "$1" = --list ]; then
  for id in $lost; do
    printf %s "$id" | grep -Eq "$UUID" && printf '%s\n' "$id"
  done
  exit 0
fi
q() { printf "'%s'" "$(printf '%s' "$1" | sed "s/'/'\\\\''/g")"; }
n=0
for id in $lost; do
  printf %s "$id" | grep -Eq "$UUID" || continue
  { IFS= read -r cwd; IFS= read -r title; IFS= read -r tag; IFS= read -r cfg; } < "$REC/$id"
  cmd="claude --resume $id"
  [ -n "$cfg" ] && cmd="CLAUDE_CONFIG_DIR=$(q "$cfg") $cmd"
  "$B/bin/band-new" --no-attach -n "$title" ${tag:+-t "$tag"} -C "$cwd" -- "$cmd" >/dev/null && rm -f "$REC/$id"
  n=$((n + 1)); [ "$n" -ge 12 ] && break
done
[ "$1" = --no-attach ] || [ "$n" -eq 0 ] || "$B/bin/band-attach" --no-restore
  • Lost vs current uses the server-started marker, so restore also works after a new server has started (e.g. band-new ran before band-attach): older records stay lost instead of being pruned as stale. band-attach counts lost records with band-restore --list.
  • Oldest first, at most 12 per run; the rest stay for the next run. Each relaunch fires SessionStart with the same id, which rewrites the record as current.
  • A session whose transcript is gone fails --resume in its pane; the window shows the error and can be closed with ✕.
  • Only the account (CLAUDE_CONFIG_DIR) carries over. Other launch flags (--model, --permission-mode, --settings) are not recorded, so the resumed session starts with the CLI defaults.
  • Records lost for over 24 h are dropped, so a restore after a reboot works within a day.
  • TMUX_BIN above is resolved as in section 3; xargs -n1 basename on an empty list prints nothing.

Left to the builder

These do not change what the user sees, and either choice conforms: how band-new parses unknown flags (exit 2 is fine); whether a same-second config edit is re-sourced; where the attach prompt is printed; whether noteRepo is awaited; the CLI of hooks.mjs; backups on uninstall; extra exports from sidebar-core.mjs.

10. Traps

  • Window names are format-expanded. #(cmd) in a name runs a shell command. Escape # as ##; skip -c for a directory containing #.
  • A trailing ; ends a tmux command. Trim it from option values and titles. For the command line typed with send-keys -l, where it is part of the command (find … ;), rewrite a final ; as \;, which tmux turns back into ; (tmux 3.8).
  • -f is read once. A re-source replaces global hooks instead of duplicating them.
  • zsh expands an unquoted =band to the path of a command named band. Quote the attach target.
  • Server environment. Whatever environment starts the tmux server is inherited by every pane, and without LANG tmux draws ● ✓ ◌ as _. Start it with env -i plus PATH HOME USER LOGNAME SHELL TMPDIR SSH_AUTH_SOCK DISPLAY WAYLAND_DISPLAY XDG_RUNTIME_DIR DBUS_SESSION_BUS_ADDRESS from the caller (each only when set; the last four are a Linux desktop session's, for browser logins, the clipboard and the keyring), LANG (caller's, else en_US.UTF-8), TERM=xterm-256color, COLORTERM=truecolor.
  • kill-server leaves the socket file. Test for a server with list-sessions, never with the socket's existence.
  • No click target on pane borders. tmux has clickable ranges on the status line only, which is why close lives in the sidebar.
  • A new window has no state until its first hook fires, which is why ✕ confirms for an empty state.

11. Security note

Anything that can connect to the tmux socket can run commands in your panes, outside any sandbox the agent in that pane runs under; anything that can write state/sessions/ picks which folders a restore resumes in. Keep B at mode 0700. If you run agents in a sandbox (Claude Code's sandbox setting, codex's seatbelt), deny B to them and check that a sandboxed command cannot connect to the socket: from inside a sandboxed agent, tmux -S <socket> list-windows must fail. Claude Code's sandbox denies unix socket connects unless allowUnixSockets is set; do not set it.
